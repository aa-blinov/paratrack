## API-токены

«Настройки» → «API-токены» → «Создать токен». Токен начинается с `pt_` и показывается один раз: скопируйте его сразу и храните как пароль.

- **Действует до**: 30 дней, 90 дней, год или бессрочно.
- **Только чтение**: токен не сможет ничего менять. Для отчётов и выгрузок этого хватает.
- Токен работает в том пространстве, где его создали, и от вашего имени, с вашими правами. Если вас уберут из пространства, токен перестанет работать.

Запросы с токеном идут с заголовком:

```
Authorization: Bearer pt_…
```

## REST API v1

| Метод и путь | Что делает |
|---|---|
| `GET /api/v1/sessions` | сессии за период, закрытые и идущие |
| `POST /api/v1/sessions` | запустить таймер: поля `activity`, `note` |
| `PATCH /api/v1/sessions/{id}` | поправить сессию: `start_at`, `end_at`, `duration`, `note` |
| `DELETE /api/v1/sessions/{id}` | удалить сессию |
| `GET /api/v1/projects` | проекты пространства |
| `GET /api/v1/reports/summary` | итог за период: всего секунд и разбивка по активностям |

Период задаётся параметрами `from` и `to` в виде `ГГГГ-ММ-ДД`. По умолчанию это последние 30 дней. Участник через API видит и меняет только свои сессии, как и в интерфейсе. Ставки проектов в ответе есть только для владельца и администраторов.

`PATCH /api/v1/sessions/{id}` принимает поля формы `start_at`, `end_at`, `duration` и `note`. Успешный ответ — JSON `{"updated": <id>}`.

### Пагинация сессий

`GET /api/v1/sessions` отдаёт сессии страницами, от новых к старым:

- `limit`: сколько на странице, по умолчанию 100, максимум 500;
- в ответе есть `next_cursor`, если дальше есть ещё; передайте его как `cursor`, чтобы получить следующую страницу. На последней странице `next_cursor` нет.

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "https://paratrack.duckdns.org/api/v1/sessions?from=2026-09-01&to=2026-09-30&limit=200"
# {"sessions":[{"id":812,"activity":"вёрстка","start":"2026-09-30T07:05:00Z","end":"…","seconds":5400,"note":""}, …],
#  "next_cursor":"MjAyNi0wOS0yOFQwOT…"}

curl -H "Authorization: Bearer $TOKEN" \
  "https://paratrack.duckdns.org/api/v1/sessions?from=2026-09-01&to=2026-09-30&limit=200&cursor=MjAyNi0wOS0yOFQwOT…"
```

Курсор непрозрачный: не собирайте его сами, просто передавайте обратно.

## Вебхуки

«Настройки» → «Вебхуки»: когда в пространстве что-то происходит, paratrack отправляет POST с JSON на ваш адрес. Так учёт связывается с чатом, CRM или своим скриптом.

События на выбор: таймер запущен, таймер остановлен, счёт создан, счёт оплачен, создана ссылка на оплату, импорт завершён, или все сразу.

**Подпись.** Если задать секрет, каждый запрос подписывается:

- `X-Paratrack-Signature` = hex(HMAC-SHA256(секрет, тело));
- `X-Paratrack-Signature-V2` = hex(HMAC-SHA256(секрет, `X-Paratrack-Timestamp` + "." + тело)); проверяйте эту версию и отклоняйте старые метки времени, это защищает от повтора запроса;
- `X-Paratrack-Event`: какое событие пришло.

**Доставка.** Если ваш сервер не ответил или вернул 429 или 5xx, paratrack повторит запрос ещё три раза: через 2 секунды, 10 секунд и минуту. Последние доставки с кодом ответа видны под каждым вебхуком.

На вебхуки нельзя направить адреса локальной сети и localhost. На своём сервере это разрешается переменной `PARATRACK_WEBHOOK_ALLOW_PRIVATE=1` ([Свой сервер]({{ '/docs/self-host/' | relative_url }})).

## Журнал действий

«Настройки» → «Журнал»: последние 100 событий пространства. Входы, запуски таймеров, счета, выплаты, изменения настроек и ролей, с временем, объектом и IP. Журнал видят владелец и администраторы.
