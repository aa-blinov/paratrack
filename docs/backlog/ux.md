# План UX: кратно удобнее

Не полировать всё подряд, а умножить три вещи, из которых складывается «удобно»:

1. **Скорость.** Частая операция — минимум кликов, и продукт сам называет следующий шаг.
2. **Доверие.** План, табель, счёт и выплата читаются как одна система: каждая цифра
   прослеживается до денег, каждый отказ называет реальный выход.
3. **Телефон.** Основной сценарий ЦА №1 — телефон; частые пути должны работать одной рукой.

Метрики прогоняются до/после и автоматизируются в e2e (Playwright умеет считать клики —
метод из `docs/screens/*.md`):

| Метрика | Сегодня | Цель |
|---|---|---|
| Время до первой учтённой минуты с регистрации | ~90 с | < 60 с |
| «Забыл вчера, дописать 2 часа» | ~6 кликов, форма ниже сгиба | 3 клика, триггер рядом с «Идут сейчас» |
| Черновик счёта за месяц (фрилансер) | 2–5 кликов + риск тупиков | 4 клика без тупиков |
| Неделя руководителя: утвердить + выплатить | 3 экрана, вся команда разом | 2 экрана, по человеку |
| Экраны-тупики (отказ без следующего шага) | 1 (правка выставленных часов) | 0 |
| Нарушения доступности (a11y_check) | 0 | 0, плюс проход скринридером |

Размеры: S — до дня, M — до недели, L — недели. Источники: клик-карты
`docs/screens/*.md`, разбор экранов 2026-11-19, открытые пункты соседних документов.

## Фаза 1 — «Одна система, а не четыре таблицы» (P1, 2–3 недели)

Пользователь студии сегодня держит в голове четыре несвязанные сетки: расписание,
табель, счёт, выплата. Кратно — это когда они сходятся в одну картину.

- [ ] **UX-10** (M). Табель: колонка «План / Факт / Δ» по строке дня. План берётся из
  расписания, Δ подсвечивается как на странице проекта. Источник:
  `docs/screens/schedule.md`, слабое место 5.
- [ ] **UX-11** (M). Прослеживаемость денег: в счёте — «из утверждённых недель X–Y»,
  в строке расчёта — «часы из недель X–Y» и ссылки на счета того же периода. Сверка
  выплаты со счётом клиента — сейчас невозможна в интерфейсе.
- [ ] **UX-12** (S). Табель: «Отменить правку» рядом со статусом и подтверждение при
  обнулении дня с интервалами. Источник: `docs/screens/timesheet.md`, слабое место 1.
- [ ] **UX-13** (M). Утверждение недели по одному человеку (TIME-23) и табель
  конкретного человека (TIME-24). Снятие главного барьера студии: сейчас утверждение
  замыкает всю команду разом, а владелец не видит табель сотрудника.
- [ ] **UX-14** (S). Сетки: после Enter фокус в соседнюю ячейку (сейчас — на body),
  стрелки вверх/вниз ходят по дню той же строки. Табель и расписание одинаково.
- [ ] **UX-15** (S). Счета: колонка «Ставка» в списке и подпись «ставка проекта N —
  2 500,50 ₽» в форме под выбором проекта. Сейчас ставку видно только внутри счёта.
- [ ] **UX-16** (L). Отчёт «задача → время → деньги»: закрывает разрыв, где задачи
  существуют отдельно от денег (связывает только активность). Для студии — ответ
  «сколько стоила эта задача клиенту».

## Фаза 2 — «Месячный цикл в четыре клика» (P1–P2, 3–4 недели)

Фрилансер и студия раз в месяц проходят один и тот же круг. Кратно — это когда круг
сжимается до «проверил и подтвердил».

- [ ] **UX-20** (M). Рекуррентные счета (FIN-27): «каждое 1-е число, все оплачиваемые
  проекты» — черновики создаются сами, приходит письмо «к выставлению готовы».
  Проверил, нажал «Отправить».
- [ ] **UX-21** (M). Реквизиты клиента живут в карточке клиента (CRM), счёт берёт их
  оттуда. Сейчас — из истории прошлых счетов, и первый счёт по проекту выходит
  с пустыми реквизитами из свёрнутого блока.
- [ ] **UX-22** (L). Оклады (FIN-26): половина команды владельца студии — на окладе
  (его цитата в `docs/backlog/finance.md`). Без этого выплаты для студии неполные.
- [ ] **UX-23** (M). Закрытие периода (FIN-25): «Закрыть месяц» — часы, счета и выплаты
  месяца фиксируются одним действием, задним числом отказывает с названием периода.
- [ ] **UX-24** (S). Счета: «часы уже в INV-2026-001 от 3 ноября» вместо «нечего
  выставлять» при повторном периоде. Источник: `docs/screens/invoices.md`, слабое
  место 2.
- [ ] **UX-25** (S). Проекты: бейдж «без ставки» в списке и ставка с «Оплачиваемым»
  в шапке карточки, а не в свёрнутом «Изменить» на дне экрана (сейчас 5 кликов).
  Источник: `docs/screens/projects.md`, слабое место 1.

## Фаза 3 — «Телефон как основной» (P2, 2–3 недели)

Первый экран ЦА — телефон, а мобильная проверка была только в эмуляции Chromium
(признано в `docs/JOURNEY.md`). Кратно — это когда телефон не «выживание», а обычный
способ работы.

- [ ] **UX-30** (L). Мобильный табель: вид «день» — вертикальный список дней с итогами,
  а не недельная сетка с горизонтальным скроллом. Сетка остаётся на десктопе.
- [ ] **UX-31** (S). Физическое тестирование: два реальных устройства (iOS, Android),
  чек-лист из JOURNEY, повторяется раз в месяц. Пока ни один человек не держал
  продукт в руках.
- [ ] **UX-32** (M). Обзор одной рукой: старт и стоп большими целями, «Только эта»
  — жестом, полоса «Идут сейчас» — главным элементом экрана, а не одной из карточек.
- [ ] **UX-33** (S). Тихие часы для напоминаний: не слать push ночью по поясу
  получателя, даже если воркер разбудили.
- [ ] **UX-34** (S). Офлайн: баннер показывает, что именно в очереди (сделано
  2026-11-19), теперь — автоотправка при возврате сети без перезагрузки страницы.

## Порядок и приёмка

1. Фаза 0 целиком до показа: это снятие единственного тупика, двух ложных сообщений
   и подъём второй по частоте операции на видное место.
2. Фаза 1 следующей: «одна система» — самый сильный аргумент питча после «деньги
   сходятся до копейки», потому что это видно на любом скриншоте с цифрами.
3. Фазы 2–3 чередуются по одному пункту за раз (правило README: P0 — по одному,
   крупные — отдельными инициативами).
4. Приёмка каждого пункта — строка в таблице метрик выше, снятая тем же способом,
   каким измерялись клик-карты; UX-42 закрепляет бюджеты, чтобы удобство не
   регрессировало молча.

## Не делаем

- Конструктор отчётов и «BI-режим» — пять шаблонов закрывают регламентные вопросы,
  а тянут за собой другой продукт.
- Чаты, ленты, телефония — вне продукта (решение D-6).
- Нативное приложение вместо PWA — отдельный проект (решение UI-08): фаза 3
  закрывает мобильный сценарий дешевле и без второго кода.
