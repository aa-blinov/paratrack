# MCP-сервер

paratrack отдаёт агенту те же сущности, что и человеку: клиентов, контакты, сделки, активности, календарь, проекты, задачи, сессии времени и сводку по времени. Протокол: Model Context Protocol, JSON-RPC 2.0 поверх HTTP. Версия протокола `2025-06-18`.

## Подключение

```
POST https://paratrack.duckdns.org/mcp
Authorization: Bearer pt_…
Content-Type: application/json
```

Токен создаётся в «Настройки → Токены». Токен работает в том пространстве, где его создали, и даёт права того, кто его выдал. Агент не получает больше, чем человек в форме: участник не меняет чужие сделки, а клиента создаёт только руководитель.

- Без токена или с неверным токеном ответ `401`.
- Куки браузера не принимаются. Запрос со страницы другого сайта не может выполнить инструмент от имени сессии.
- Токен «только для чтения» вызывает инструменты чтения. Инструмент записи отвечает ошибкой «Этот токен только для чтения: ничего не записано» и ничего не меняет.
- Инструменты раздела, который выключен в пространстве, исчезают из списка и отказывают при вызове. Разделы: `crm`, `calendar`, `tasks`, `goals`, `tags`, `schedule`, `invoices`, `payroll`, `integrations`. Участники и утверждённые недели доступны без раздела.

## Протокол

- Один запрос JSON-RPC на один `POST`. Пакеты (массив запросов) не принимаются: ревизия `2025-06-18` их убрала, ответ с кодом `-32600`.
- Уведомление (запрос без `id`) получает `202` без тела.
- Сессий нет: каждый запрос несёт токен.
- Методы: `initialize`, `ping`, `tools/list`, `tools/call`. Остальное отвечает `-32601`.
- Неизвестный инструмент или запрос без имени инструмента: ошибка протокола `-32602`.

Пример:

```sh
curl -s -X POST https://paratrack.duckdns.org/mcp \
  -H "Authorization: Bearer pt_…" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"deal_create","arguments":{"title":"Сайт для Ромашки","client_id":12,"amount_cents":250000}}}'
```

## Ошибки инструментов

Ошибка инструмента не ошибка протокола: ответ приходит результатом с `"isError": true`, а текст в нём на языке владельца токена. Агент читает текст и исправляет вызов.

- Неверное поле: текст «Проверьте поле» и имя поля, например `lost_reason`. Имена полей совпадают с аргументами инструмента.
- Нет прав: «Недостаточно прав для этого действия».
- Нет записи в пространстве: «Запись не найдена».
- Раздел выключен, токен только для чтения: см. выше.
- Аргумент, которого нет в схеме, отклоняется. Опечатка в имени поля не проходит молча.

## Аудит

Каждая успешная запись через `/mcp` попадает в журнал аудита: действие `mcp.write`, цель `имя инструмента`, примечание «агентом через MCP». Так видно, что изменение сделал агент, а не человек.

## Инструменты

Имена: `сущность_действие`. Даты в аргументах `YYYY-MM-DD`, моменты времени RFC 3339, суммы в центах, длительности в секундах. Поля, которые не переданы, не меняются, если в описании не сказано иное. Удалять клиентов, сделки и счета через сервер нельзя. Календарное событие удаляет его автор или руководитель, цель удаляет руководитель, сессию времени удаляет тот, кто её записал, шаг чек-листа удаляет участник пространства.

### Клиенты

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `clients_list` | `archived` | Клиенты пространства. Email, реквизиты и заметки отдаются руководителю. |
| `client_create` | `name`*, `email`, `details`, `currency`, `notes` | Создаёт клиента. Только руководитель. Имя уникально в пространстве. |
| `client_update` | `client_id`*, `name`, `email`, `details`, `notes`, `currency`, `archived` | Меняет клиента. Только руководитель. `archived` прячет клиента из выборов. |

### CRM: контакты, сделки, активности

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `contacts_list` | `client_id`* | Контакты клиента. |

| `deals_list` | `stage`, `owner_id`, `overdue` | Сделки и счётчики по стадиям, число просроченных. Просрочена открытая сделка, у которой дата следующего шага раньше сегодня. |
| `deal_create` | `title`*, `stage`, `client_id`, `contact_id`, `owner_id`, `amount_cents`, `currency`, `probability`, `close_date`, `next_step_at` | Создаёт сделку. Стадия по умолчанию `new`, владелец по умолчанию токен. Другого владельца назначает руководитель. |

| `project_create` | `name`*, `color`, `client_id`, `billable_rate_cents`, `currency`, `deadline`, `budget_cents`, `lead_user_id` | Создаёт проект, slug делается из имени. Только руководитель. |

Только руководитель. |

Пустой `due` снимает срок, `assignee_id` или `estimate_seconds` равные 0 снимают исполнителя или оценку. `status` двигает задачу по доске и уведомляет наблюдателей. |

| `task_dependency_add` | `task_id`*, `depends_on_task_id`* | Задача ждёт другую задачу того же проекта. Самоссылка и цикл отказываются. |

| `task_archive` | `task_id`*, `archived`* | Архивирует задачу, `archived` false возвращает её. Время остаётся. Руководитель или автор задачи. |

Статусы доски: `todo`, `doing`, `done`.

### Время

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `time_session_start` | `activity`*, `project_id`, `note` | Запускает таймер по названию активности. Если задача держит активность, она переходит в `doing`. Таймер не запускается, пока по активности идёт другой. |
| `time_session_stop` | `session_id`* | Останавливает таймер. Возвращает активность и секунды. |
| `time_sessions_list` | `from`, `to`, `limit`, `cursor` | Сессии, новые сверху, за дни от и до включительно. Без дат за последние 30 дней. Участник видит только свои сессии. `next_cursor` передаётся в `cursor`. |
| `time_session_add` | `activity`*, `project_id`, `start`*, `end`*, `note`, `confirm_long` | Записывает уже прошедшую сессию по названию активности; активность создаётся, если имени ещё нет. Сессия длиннее десяти часов требует `confirm_long`. Утверждённая неделя отказывает и называет закрытые дни. |
| `time_session_update` | `session_id`*, `start`, `end`, `note`, `project_id` | Меняет поля, которые переданы; без `note` заметка остаётся. Участник меняет только свои сессии, сессия утверждённой недели закрыта. `project_id` равный 0 возвращает сессию в проект активности. |
| `time_session_delete` | `session_id`* | Удаляет сессию времени. Участник удаляет только свои, сессия утверждённой недели закрыта. Необратимо. |
| `time_edit_request_create` | `activity_id` или `activity`, `day`*, `minutes`*, `reason`* | Просит изменить время активности за день, как ячейка табеля: предложенные минуты станут итогом дня, когда руководитель одобрит. Активность по `activity_id` или по названию, поиск без создания. Может любой участник, только для своего времени. |
| `time_edit_request_decide` | `request_id`*, `approve`*, `note` | Одобряет или отклоняет ожидающую заявку на изменение времени. Только руководитель. |
| `report_summary` | `from`*, `to`* | Всего секунд за дни и секунды по активностям. |

| `invoices_list` | | Счета: номер, клиент, статус, период, срок оплаты, суммы в центах. Только руководитель. |
| `invoice_get` | `invoice_id`* | Один счет со строками и журналом оплат. Только руководитель. |
| `payroll_runs_list` | | Ведомости выплат: номер, период, статус, суммы. Только руководитель. |

Удалять счета и ведомости, открывать утверждённую неделю и удалять пространство агент не может: он только ставит запрос в очередь (ниже), а подтверждает его человек в приложении. Возвращать оплаченную ведомость нельзя. Отправка счёта и выплата ведомости доходят до клиента и участников и не отменяются.

### Очередь подтверждений

Четыре действия агент может только запросить. Запрос ждёт в очереди, пока человек подтвердит его или отклонит в приложении: «Настройки» → «Подтверждения». Страница видна владельцу и администраторам. Удаление пространства подтверждает только владелец. Подтверждение выполняет то же действие, что соответствующая страница, от имени того, кто подтвердил, и его правилами. Если действие отказало, запрос остаётся в журнале со статусом «не выполнен» и причиной. Отклонение ничего не выполняет. Токен агента не может подтвердить или отклонить запрос: эти действия доступны только в браузере.

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `invoice_delete_request` | `invoice_id`*, `reason`* | Просит удалить черновик счёта. Ничего не удаляет. Отправленный счёт не запрашивается. Только руководитель. |
| `payroll_run_delete_request` | `run_id`*, `reason`* | Просит удалить черновик ведомости. Ничего не удаляет. Выплаченная ведомость не запрашивается. Только руководитель. |
| `week_reopen_request` | `week_start`*, `reason`* | Просит снять утверждение недели, как кнопка на табеле. `week_start` первый день недели. Ведомость, покрывающая неделю, останавливает снятие при подтверждении. Только руководитель. |
| `workspace_delete_request` | `reason`* | Просит удалить пространство. Подтвердить может только владелец. Пространство с другими участниками при подтверждении не удалится. Только владелец. |

Повторный запрос на тот же объект, пока первый ждёт решения, возвращает уже стоящий в очереди запрос.

### Администрирование: только чтение

Эти инструменты читают то же, что страницы настроек. Ни один не отдаёт секрет: ни подпись вебхука, ни токен, ни ключ, ни ссылку-приглашение.

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `webhooks_list` | | Адреса вебхуков, события, активен ли, последняя доставка. Только владелец, как страница вебхуков. |
| `integrations_list` | | Интеграции: провайдер, имя, состояние (`ok` или `failed` с текстом последней ошибки синхронизации), дата подключения. Видят все участники. |
| `api_tokens_list` | | Свои API-токены: id, имя, префикс, только чтения, создан, последнее использование. Чужие токены не видны. |
| `workspace_settings_get` | | Имя, часовой пояс, первый день недели, автоблокировка, валюта, округление, префикс счёта, НДС и примечание, реквизиты. Вместо ключа Stripe только `stripe_key_set`. Только руководитель. |
| `invitations_list` | | Приглашения: состояние (`open`, `accepted`, `expired`), роль, создано, истекает. Отозванное приглашение удаляется и в списке не появляется. Только руководитель. |

`*` отмечает обязательный аргумент.

## Что не входит

- Потоковые ответы (SSE) и OAuth. Токен `pt_` единственный способ входа.
- Версия протокола `2026-07-28`: поддержка после проверки по тексту спецификации (backlog CRM-20).
- Пакеты JSON-RPC.
