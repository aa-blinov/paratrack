# Интеграции — `/integrations`, `/integrations/marketplace`, `/integrations/{id}`

Экран подключения внешних трекеров задач: форма подключения, список
подключённых, карточка маркетплейса и страница одной интеграции с её задачами.

## Смысл экрана

Экран нужен тем, кто хочет запускать таймер прямо из задачи или карточки
внешнего сервиса, а не из paratrack. Он состоит из трёх частей. Вверху —
форма «Подключить источник»: провайдер, название подключения, ключ доступа и
необязательное поле «Откуда брать задачи». Подсказки под полями меняются
вместе с провайдером (`web/src/integrations/integrations-page.tsx:43-44`), так
что для Jira объясняется формат `email:api-token` и JQL, для Trello — `key:token`
и id доски. Ниже — карточка «Подключено» с уже подключёнными источниками, а
если их нет, пустое состояние «Интеграции пока не подключены» с приглашением
открыть маркетплейс.

Маркетплейс (`/integrations/marketplace`) — витрина, а не список установленного.
В ней 11 карточек: восемь доступных (GitHub, GitLab, Jira, ClickUp, Asana,
Trello, Notion, Todoist) с настоящими фавиконками, кратким описанием и
требованиями к ключу, и три помеченные «скоро» (monday.com, Basecamp, Slack) без
кнопки. Отличие от формы в том, что маркетплейс ничего не подключает сам:
его кнопка «Подключить» ведёт на `/integrations?provider=<id>`, где провайдер
уже выбран. Проверено: `?provider=github` действительно предустанавливает
значение, так что маркетплейс — это витрина с подсказками, а подключение
всегда происходит на странице выше.

Страница одной интеграции (`/integrations/{id}`) почти пустая: крошка
«Интеграции / <название>», само название, кнопка «Синхронизировать» и карточка
«Задачи (N)», где у каждой задачи есть заголовок, внешний id, статус и кнопка
«Старт». Это всё, что нужно для основного сценария — начать таймер по задаче,
— но на этой странице нет ни токена, ни статуса подключения, ни даты последней
синхронизации: на странице с «Задачи (0)» формально только две формы, отправка
и выход.

подключение создано и затем удалено через интерфейс.

## Слабые места

| Что | Почему мешает | Как снимается |
|---|---|---|
| Неверный ключ всё равно создаёт подключение | Подключился GitHub с заведомо нерабочим токеном — и всё равно появился `/integrations/1` со строкой в списке «Подключено». Флеш на странице подключения: «Не удалось загрузить задачи: github 401». То есть отказ проверки не мешает создать запись, и человек уходит с «подключённой» интеграцией без задач | Не создавать запись, пока задачи не загрузились: показывать ошибку на форме и оставлять возможность поправить ключ на месте |
| Ключ нельзя посмотреть и нельзя заменить | Страница подключения содержит только две формы — синхронизация и выход, полей типа `password` там ноль. Токен пишется один раз и больше не виден нигде: чтобы сменить протубший ключ, надо удалить подключение и создать заново | Поле «Обновить ключ» на странице подключения с подтверждением, без потери названия и задач |
| Удаление в один клик без подтверждения | Форма удаления не несёт `data-confirm`, а подтверждение в приложении работает только для форм с этим атрибутом (`internal/web/static/js/app-form-actions.js:21-41`). Проверено: один клик по ✕ — и подключение исчезло, диалога не было. Для сравнения, удаление тега спрашивает подтверждение | Диалог «Удалить интеграцию? Задачи и название исчезнут» — как при удалении тега |
| Статуса подключения нет нигде | Строка в списке — это бейдж с именем провайдера, название, число задач и корзинка. Ни «работает», ни «ключ протух», ни «синхронизировано в 14:20» не показано. На странице подключения — тоже: кнопка «Синхронизировать» и «Задачи (N)». Единственный признак поломки — флеш, который живёт до перезагрузки | Бейдж статуса в строке списка и «Синхронизировано <дата>» на странице подключения; состояние «ошибка» с датой последней неудачи |
| Провал синхронизации не предлагает выход | «Синхронизировать» с испорченным ключом даёт «Не удалось загрузить задачи: github 401» — сырой код провайдера на русском фоне — и всё. Дальше на странице только пустая карточка «Задачи (0)» | Рядом с ошибкой кнопка «Обновить ключ» |
| Один и тот же провайдер назван по-разному на двух соседних экранах | В форме список собирается как `id[0].toUpperCase()+id.slice(1)` (`web/src/integrations/integrations-page.tsx:41`) и даёт «Github», «Gitlab», «Clickup». В маркетплейсе те же сервисы подписаны правильно: «GitHub», «GitLab», «ClickUp» | Словарь имён провайдеров и в форме, и в маркетплейсе |
| Уже подключённый провайдер в маркетплейсе всё ещё предлагает «Подключить» | Проверено: у карточки GitHub рядом стоял бейдж «подключено» и живая кнопка «Подключить». Человек не понимает, создаст он второе подключение или обновит первое | На подключённой карточке заменить кнопку на «Открыть» со ссылкой на `/integrations/{id}` |

## Что проверить вручную

- Настоящие ключи всех восьми провайдеров: у каждого свой формат
  (`key:token` у Trello, `email:api-token` у Jira, `glpat-` у GitLab,
  `ntn_` у Notion), и подсказки под полями стоит сверить с тем, что сервис
  реально принимает.
- Self-hosted GitLab и Jira Data Center: подсказка про «свой сервер адресом
  первым» требует живого стенда.
- Поведение при гонке двух синхронизаций — за это отвечает строка
  `int.syncSuperseded` («Пока шла синхронизация, запустилась новая.
  Обновите страницу…»), воспроизводится только высокой нагрузкой.
- Права и выключенный раздел: при `mods.integrations === false` пункт меню
  исчезает, а в меню пользователя ссылка тоже не рендерится
  (`web/src/shell/app-shell.tsx:40`) — нужен аккаунт без прав.
- Много подключений одного провайдера: экран нигде не спрашивает, можно ли
  их завести два, и в списке они неразличимы, кроме названия.
