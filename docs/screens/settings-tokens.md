# API-токены — `/settings/tokens`

Здесь выпускают ключи для скриптов и браузерного расширения и отзывают их: человек
уходит с экрана, унеся в буфер freshly созданный секрет или увидев, какой из
старых ключей пора отозвать.

## Смысл экрана

Экран отвечает на два вопроса: «каким ключом я обращаюсь к API от своего имени» и
«какой ключ больше не нужен». Вход дешёвый: в меню пользователя справа сверху есть
прямая ссылка «API-токены», поэтому с обзора экран открывается двумя кликами без
прокрутки. Второй путь тоже двухкликовый, но с прокруткой сайдбара на 239px:
пункт «Под себя» стоит на `y=920` при высоте окна 900, а видимая часть сайдбара
кончается на `y=714` (проверено: `itemBottom=952`, `scrollHeight=864`,
`clientHeight=585` у прокручиваемого `div`), дальше 1 клик по вкладке
«API-токены» в строке вкладок на `y=130`.

Вкладок в строке настроек десять, все на одной строке и все на первом экране:
Профиль, Интерфейс, Уведомления, Пространство, Разделы, Участники, Приглашения,
API-токены, Вебхуки, Журнал. Под строкой вкладок — описание из
`set.desc.settings-tokens`: «Ключи для скриптов и интеграций: запросы к API от
вашего имени. Токен показывается один раз, храните его как пароль.»

Форма создания — одна строка: поле «Имя» (`x=312`, `y=319`, 36px), селект «Действует
до» (`x=1131`, `y=319`) и кнопка «Создать токен» (`x=1240`, `y=319`). Под ними
чекбокс «Только чтение: токен не сможет ничего менять» на `y=369` и подсказка
`tokens.scopeHint`: «Токен работает в текущем пространстве и от вашего имени. Для
отчётов и выгрузок хватит «только чтения».» Всё до первого токена помещается в
первый экран: высота страницы 900px, прокручивать нечего.

Секрет показывают один раз. `handleAPITokenCreate` не делает редирект, а
перерисовывает страницу с сырым значением в ответе и заголовком
`Cache-Control: no-store` (`handlers_tokens.go:107` и `:47` — комментарий в коде
прямо объясняет, почему не редирект: секрет не должен попасть в историю и логи).
На измеренном экране карточка с секретом стоит выше формы и списка: текст
«Скопируйте токен сейчас, он показывается только один раз.» и сам секрет в
`<code>` на `y=289`, то есть на первом экране без прокрутки. Кнопка «Копировать»
рядом; после клика надпись меняется на «Скопировано», буфер обмена проверен —
в нём лежит значение вида `pt_ca8d7d5d…`.

Список токенов хранит только префикс. После перезагрузки страницы карточка с
секретом исчезает целиком (`document.querySelectorAll('code')` пуст), в списке
остаётся строка `pt_ca8d7d5d…`. Старые секреты не восстановить: обработчик отдаёт
`t.Prefix`, а не значение (`handlers_tokens.go:35`). Каждая строка показывает имя,
префикс, права («чтение» или «чтение и запись»), срок и кнопку «Удалить»; у
истёкшего токена срок красный, но отдельного статуса «истёк» нет.

Список токенов — не по пространству, а по пользователю: запрос идёт с
`APITokenListRequest{UserID: u.ID, CallerID: u.ID}` (`handlers_tokens.go:23`), а
создание — с `TeamID: teamID(r)` (`handlers_tokens.go:88`). Поэтому в строке есть
«Пространство: Александр Блинов», и токен из другого пространства будет виден
здесь же, но создать его можно только из того пространства, в котором вы сейчас
находитесь.

## Пользовательские истории

| Я | хочу | чтобы | экран |
|---|---|---|---|
| Разработчик | выпустить ключ для скрипта | вставил имя, нажал «Создать токен» и сразу скопировал секрет | API-токены |
| Разработчик | ключ только для выгрузок отчётов | токен создан с галочкой «Только чтение» и в списке подписан «чтение» | API-токены |
| Владелец студии | понять, что старый скрипт скомпрометирован | отозвал ключ и увидел подтверждение, что его больше нет | API-токены |
| Разработчик | найти нужный ключ среди нескольких | отличил их по имени, началу (`pt_f580dafd…`) и сроку | API-токены |
| Новичок | понять, можно ли ключ посмотреть ещё раз | прочитал «показывается только один раз» до того, как закрыл страницу | API-токены |

## Слабые места

| Что | Почему мешает | Как снимается |
|---|---|---|
| После удаления токена показывается «Участник удалён.» | Редирект отдаёт `flash=removed`, а `decodeFlash` переводит этот код в `flash.removed` = «Участник удалён.» (`handlers_teams.go:252-253`), и этот же код использует удаление токена (`handlers_tokens.go:122`). Человек удалил ключ, а экран говорит про участника — сообщение выглядит как ошибка чужой операции. Проверено: после удаления `?flash=removed`, `role=status` содержит «Участник удалён.» (`settings-tokens-07-after-delete-flash.png`) | Свой код флеша для токенов: `flash.tokenRemoved` = «Токен отозван.» |
| Отзыв токена — один клик без подтверждения | Кнопка «Удалить» сама отправляет форму `POST /api/tokens/{id}/delete` (`tokens-page.tsx:34`); ни диалога, ни двухшагового подтверждения нет — проверено, что после клика сразу уходит редирект, а число токенов уменьшается. Скрипт, который работает на этом токене, отваливается, и восстановить ключ нельзя | Подтверждение с названием токена, как у «Удалить сессию» на `/stats` |
| Область действия токена ограничена только галочкой «чтение» | В форме два параметра: имя и срок, плюс `read_only`. В `TokenOptions` (`internal/appmodel/edit_fields.go:37-41`) только `TeamID`, `ExpiresAt`, `ReadOnly` — списка разрешений нет. Ключ на чтение всё равно читает счета, выплаты и все участников пространства; ограничить ключ одним разделом нельзя | Чекбоксы прав: отчёты, счета, участники; показывать, что даёт «только чтение» списком разделов, а не одной фразой |
| Дату создания токена не показывают, хотя она есть | В `tokenRow` есть поле `Created`, обработчик его заполняет (`handlers_tokens.go:36`), а разметка его не рисует (`tokens-page.tsx:34`). В строке видны только имя, префикс, права и срок; когда ключ создан, по списку не определить. Порядок — только по имени, сортировки нет | Вывести дату создания в строку и отсортировать список по убыванию даты |
| Секрет исчезает при первом же уходе со страницы и ни о чём не предупреждает | Карточка живёт только в ответе на POST; предупреждения «уйти — потеряете секрет» нет ни в `beforeunload`, ни в тексте (`tokens-page.tsx:26`). Единственная защита — строка «Скопируйте токен сейчас», а кнопка «Копировать» не выделена: это вторая кнопка в строке с текстом | Предупреждение при уходе, пока секрет не скопирован; отдельный акцент на копировании |
| Срок по умолчанию — 90 дней, и «Бессрочно» спрятан в селекте | «Бессрочно» — четвёртый вариант выпадающего списка (`tokens-page.tsx:30`), для скрипта, который должен жить годами, это надо специально выбрать; в списке нет даты создания, по которой видно, что ключ скоро протухнет | Показывать «через N дней» рядом с секретом; вынести бессрочный вариант в отдельную галочку «не истекает» |
| Второй путь на экран требует прокрутки сайдбара, первый спрятан в меню пользователя | «Под себя» стоит на `y=920` при окне 900 (нужно 239px прокрутки), а в меню пользователя есть прямая ссылка «API-токены». Два входа с разной глубиной, и очевидный для новичка — с прокруткой | Ссылка «API-токены» в меню пользователя и в сайдбаре |

## Что проверить вручную

- Поведение после отзыва ключа, который сейчас использует браузерное расширение:
  в браузере ошибка 401 приходит на следующем запросе, на `/settings/tokens` это
  никак не видно — нужно проверить руками, достаточно ли сообщения об отзыве.
- Что показывает экран, когда список обрезан: в коде ограничения на число токенов
  нет, но на 50+ токенах страница перестанет помещаться в первый экран — как
  выглядит список и где окажется кнопка удаления.
- Истечение токена: срок в списке становится красным, но что происходит при
  попытке использовать протухший ключ с `/api/v1/me` — проверяется только вручную.
- Токен из второго пространства: список берётся по пользователю, а не по
  пространству, поэтому ключ, созданный в «Студия «Ясень»», должен появиться и
  здесь, в строке с названием пространства. Само переключение пространств на
  десктопе не воспроизводится (см. `docs/screens/settings-audit.md`), поэтому
  проверено только по коду.
- Горячие клавиши на этом экране не искались — если они есть, стоит их
  зафиксировать.
