# Теги — `/tags`

Экран тегов: список меток, которыми подписывают сессии поперёк активностей
и проектов, плюс форма создания новой метки.

## Смысл экрана

Тег — это второй, свободный отрезок группировки: активность отвечает на
«чем занимался», проект — на «заказчика», тег — на «в каком режиме»
(`#глубокая-работа`, `#встреча`, `#urgent`). Экран состоит из двух блоков:
форма «Новый тег» сверху (одно поле «Имя» с подсказками из `datalist` и
кнопка «Добавить») и карточка «Все теги (N)» снизу, где каждый тег — бейдж
вида `#глубокая-работа / 0`: слева имя, справа моноширинный счётчик сессий
с подсказкой «сессий с этим тегом» (`internal/i18n/dict/ru.json:714`).

Главная особенность экрана в том, что **сам он ничего не умеет, кроме
создания и удаления**. Ни привязки тега к сессии, ни фильтра по тегу здесь
нет — и оба эти действия экран передаёт другому: «Ставятся на строке сессии
в статистике» и «Нажмите на тег в строке сессии, и статистика покажет
только эти сессии» (`internal/i18n/dict/ru.json:155`, `:164`). Ссылок на
статистику в тексте нет: ни одного элемента со ссылкой на `/stats` на
странице не рендерится, а в коде вне сайдбара ссылок на `/tags` тоже нет —
это тупиковый экран, в который ведёт только пункт меню «Теги».

Удаление есть: маленькая корзина внутри каждого бейджа с
`aria-label="Удалить тег: <имя>"` (`web/src/tags/tags-page.tsx:71`).
Подтверждение — диалог «Удалить тег? Он снимется с сессий», кнопки
«Отмена» / «Подтвердить». Счётчик рядом с тегом при этом ничего не
говорит о том, сколько сессий будет потеряно, потому что удаление идёт по
всем сразу.

## Пользовательские истории

| Я | хочу | чтобы | экран |
|---|---|---|---|
| Я | завести метку `#ревью` до того, как начну разбирать правки | метка появилась в списке со счётчиком 0 | теги |
| Я | посмотреть, какие метки вообще есть | в карточке «Все теги (N)» видны все имена и число подписанных сессий | теги |
| Я | убрать ошибочно созданную метку | после подтверждения бейдж исчез, остальные не тронуты | теги |
| Я | подписать сессию меткой `#встреча` | метка появилась чипом в строке сессии, и по ней фильтруется статистика | статистика |
| Я | посмотреть только сессии с `#встреча` | статистика показала отфильтрованный список | статистика |

## Клики до действий

Считано от состояния «вошёл, десктоп 1440×900, сайдбар раскрыт, обзор».
Ввод текста кликом не считается.

| Действие | Кликов | Путь | Горячие клавиши |
|---|---|---|---|
| Открыть экран тегов | 1 | 1 (меню → Теги). Других входов на экран нет: ни с обзора, ни со статистики | — |
| Создать тег | 2 | 2 (меню → Теги → «Добавить») | — |
| Удалить тег | 3 | 3 (меню → Теги → ✕ в бейдже → «Подтвердить») | — |
| Переименовать тег | пути нет | Контрола на экране нет, и в API только GET/POST/DELETE (`internal/web/routes_api.go:33-35`) | — |
| Привязать тег к сессии | 2 | 2 (меню → Статистика → «Повесить тег» в строке сессии) + скролл: поля «+ тег» лежат ниже первого экрана | — |
| Снять тег с сессии | 2 | 2 (меню → Статистика → ✕ на чипе тега) | — |
| Отфильтровать статистику по тегу | 2 | 1 (меню → Теги) + 1 (клик по `#тег` → `/stats?period=week&tag=…`) | — |

Привязка тега — перекрёстный путь: с `/tags` её не сделать вовсе, только
с `/stats`, и на 1440×900 первое поле находится на `y ≈ 926`, то есть
требует прокрутки (высота страницы 1670 px при высоте окна 900 px).

Горячих клавиш нет.

## Слабые места

| Что | Почему мешает | Как снимается |
|---|---|---|
| Переименования нет ни в интерфейсе, ни в API | Опечатку в имени («глубокая работа» вместо «глубокая-работа») исправить нечем: у бейджа есть только корзина, а `internal/web/routes_api.go:33-35` описывает лишь список, создание и удаление. Выход — удалить тег и создать заново (3 + 2 клика), причём удаление снимает метку со всех сессий | Переименование прямо в бейдже или в диалоге удаления: «переименовать в…» с сохранением связей с сессиями |
| Создать метку — только половина дела, вторая половина на другом экране | После «Добавить» в списке появляется тег со счётчиком 0, и экран об этом не говорит: подписать им сессию по-прежнему нужно вручную в статистике, а новый тег сам по себе никуда не ведёт | Ссылка «Перейти в статистику и подписать сессию» прямо под новым тегом со счётчиком 0, или счётчик 0 как приглашение кликнуть |
| ~~Экран без выхода из себя~~ **закрыто наполовину** | Сам тег теперь ссылка: клик по `#встреча` на `/tags` открывает `/stats?period=week&tag=встреча` (`tags-page.tsx:94`), и подсказка под списком об этом говорит. Но перехода к сессии по-прежнему нет, а бейдж тега в строке сессии на `/stats` остаётся без ссылки (`stats-page.tsx:74`) | Ссылка на тег в строке сессии, чтобы фильтр открывался и оттуда |
| Привязка тега спрятана ниже первого экрана статистики | Поля «+ тег» в строках сессий начинаются с `y ≈ 926` при высоте окна 900: первый шаг после перехода в статистику — прокрутка, а полей четыре, и каждое помечено только именем активности | Вынести добавление тега в правую панель сессии или в верхнюю панель списка сессий, чтобы поле было видно сразу |
| Создание тега не проверяет имя | `datalist` подсказывает существующие имена, но любой текст принимается и создаёт новый тег — рядом с «глубокая-работа» может появиться «глубокая работа» без всякого предупреждения | Проверка близких имён перед созданием: «уже есть #глубокая-работа, создать #глубокая работа?» |
| Один клик удаляет метку со всех сессий, а диалог не перечисляет потери | Текст диалога «Удалить тег? Он снимется с сессий» одинаков для тега с 0 сессий и с сотней; счётчик у бейджа виден, но в диалог не переносится | В диалог добавить «снимется с N сессий», а для N > 0 — список первых сессий или подтверждение на отдельном шаге |
| Экран без выхода из себя | С экрана нельзя перейти ни к сессии, ни к статистике — только текст. Возврат стоит отдельного клика по меню, а экран при этом — тупик: ссылок на `/tags` нет ни на одном другом экране | Ссылка на статистику в подсказке и кнопка возврата, экран добавляется в ссылки из строки сессии |

## Что проверить вручную

- Длинные имена и кириллица в бейджах: перенос, обрезка по `max-w-full`
  и вид диалога удаления, когда имя длинное.
- Много тегов (20+): сколько рядов бейджей, виден ли список без скролла и
  не разъезжаются ли корзинки при переносе.
- Переименование в обход приложения: тег с пропаленной буквой в статистике
  фильтруется или нет — автоматикой не проверить.
- Права: у участника без `CanManage` корзины в бейджах не рендерятся вовсе
  (`web/src/tags/tags-page.tsx:71`) — нужен второй аккаунт без прав.
- Гонка с чужой сессией: удаление тега, который в этот же момент повесили
  на сессию в другом браузере.
