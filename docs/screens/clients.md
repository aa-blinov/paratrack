# Клиенты — `/clients`, `/clients/{id}`

Каталог, кому выставляются счета. До появления карточки получатель жил в
трёх колонках проекта (`projects.client_name`, `client_details`,
`client_email`), то есть один и тот же заказчик на двух проектах был двумя
несвязанными записями, и на втором счёте его адрес набирался заново.

## Смысл экрана

`/clients/{id}` — страница одного клиента: его проекты, его счета, его
заметки и реквизиты. Из списка на неё ведёт само имя клиента.

`/clients` — каталог. В шапке
заголовок, объяснение и две кнопки: показать/скрыть архивных и «Новый
клиент». Клиент без проектов показан прочерками, а не нулями: у него нет
ставки, по которой что-то считать.

Форма создания видна только руководителю (`CanManage`), и на пустом экране
она же объясняет, что делать. В списке по каждому клиенту четыре числа:
сколько проектов, сколько отработано, сколько выставлено и сколько ждёт
счёта. Все четыре — производные от фактического времени, а не от оценок.

Правка карточки раскрывается на месте (`Изменить`) отдельной формой с теми
же полями. Удаления нет: карточка уходит в архив, потому что счета, которые
ей адресованы, остаются нужными. Вернуть можно ссылкой в карточке.

Живая разметка: `web/src/clients/clients-page.tsx`. Данные приходят из
`clientsPageData` (`internal/web/handlers_clients_pages.go`), маршруты —
`internal/web/routes_pages.go`. Пункт меню добавляется в `navItems`
(`internal/web/prefs.go`), он помечен `manage: true`, поэтому участник
раздела не видит.

## Поля карточки

| Поле | Куда идёт | Зачем |
|---|---|---|
| Название | уникально внутри команды | то, что печатается в счёте и ищется в справочнике |
| Почта | заголовок письма со счётом | пусто — значит счёт отправляется вручную, кнопку «отправить» предлагать нельзя |
| Адрес и реквизиты | блок получателя в счёте | копируется в документ в момент выставления |
| Валюта | переопределяет валюту команды для этого клиента | пусто — «как у команды», то же поведение, что у проекта |
| Заметки | только внутрь | цена по договору, кто оплачивает; в счёт не печатаются |

## Клики до действий

Замерено кликом в браузере на стенде `scripts/qa-env.sh up`, 1440×900, сайдбар
раскрыт; отсчёт — от состояния «вошёл в приложение, нахожусь на обзоре».
Ввод текста и выбор значения в полях отдельно не считались.

| Действие | Кликов | Путь |
|---|---|---|
| Открыть каталог | 1 | меню «Клиенты» |
| Завести клиента | 2 | меню «Клиенты» → заполнить форму → «Сохранить» |
| Изменить карточку | 3 | меню «Клиенты» → «Изменить» у клиента → правка → «Сохранить» |
| Убрать клиента в архив | 3 | меню «Клиенты» → «Изменить» → «В архив» |
| Вернуть из архива | 2 | меню «Клиенты» → показать архивных → «Вернуть» |
| Привязать клиента к существующему проекту | 5 | меню «Проекты» → карточка проекта → «Изменить» → выбор клиента → «Сохранить» |
| Задать бюджет существующему проекту | 4 | меню «Проекты» → карточка проекта → «Изменить» → «Бюджет» → «Сохранить» |
| Привязать клиента новому проекту | 8 | меню «Проекты» → «Новый проект» → «Создать» → «Изменить» → выбор клиента → «Сохранить» |
| Открыть страницу клиента | 1 (из каталога) | клик по имени клиента в списке |
| Посмотреть проекты и счета клиента | 2 | меню «Клиенты» → имя клиента |

Отдельно: пункт «Клиенты» в меню добавляется в **React-таблице**
`web/src/components/app-sidebar.tsx`, а Go-список `navItems` в
`internal/web/prefs.go` кормит только мобильные табы и экран настроек.
Регистрация маршрута в Go сама по себе делает страницу недостижимой из
десктопного меню — это уже случалось один раз.

## Слабые места

| Что | Почему мешает | Как снимается |
|---|---|---|
| Заметки видны и в списке, и на странице клиента, но нигде не участвуют в счёте | записал «оплачивает бухгалтерия» — открываешь счёт и ищешь это в голове | строка заметки в самом счёте или в его шапке |
| Создать клиента можно только с пустого места на экране — кнопка ведёт на якорь формы | при заполненном списке форма всегда сверху, то есть кликать приходится через длинную прокрутку | отдельная страница создания или модалка |

| Нет связи «клиент → его проекты» на списке | видно только число | ссылка на фильтр проектов по клиенту |


## Что проверить вручную

- Счёт, выставленный клиенту, у которого валюта отличается от валюты
  команды: какая попала в документ и совпадает ли она с подписью на
  странице клиента.
- Клиент с проектом без ставки: показывается прочерк, а не ноль.
- Архивный клиент в выпадающем списке проекта: его не должно быть, иначе
  можно привязать новую работу к клиенту, которого уже нет.
- Переименование клиента: счета, выставленные до переименования, должны
  остаться с прежними реквизитами.

## Источники

- `internal/db/schema.sql` — таблица `clients`.
- `internal/db/clients.go` — CRUD, проверка принадлежности к команде,
  расчёт бюджета по проектам.
- `internal/db/migrations.go` — перенос получателей из проектов в карточки.
- `internal/clients/` — workflow-пакет (порты, атомарные мутации).
- `internal/web/handlers_clients_pages.go` — каталог, страница клиента и
  выбор источника валюты; `view_projects.go` — блок бюджета.
- Валюта счёта выбирается по правилу **клиент → проект → пространство**,
  и подпись источника («Валюта клиента») показывается рядом с суммой.
- `e2e/test_clients.py` — сквозной сценарий: карточка, дубль имени,
  привязка к проекту, бюджет и его очистка.
