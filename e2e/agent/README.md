# Проверка агентом по персонам

Этап 4 рабочего цикла (см. `docs/WORKFLOW.md`). Claude-агент работает через встроенный браузер
(`mcp__Claude_Browser__*`), проходит сценарии персоны и записывает, что увидел.

## Как запускать

1. Стенд поднят и засеян: `bash scripts/qa-env.sh up`, затем `python3 e2e/personas/seed.py`.
2. Агент открывает `http://127.0.0.1:8890/login` и входит под аккаунтом персоны из
   `e2e/personas/personas.json`. Пароль общий для всех персон и только тестовый.
3. Агент идёт по шагам из `e2e/agent/journeys/<персона>.md` по порядку. Шаг не пропускается.
4. На каждом шаге агент сверяет результат с ожиданием и записывает вердикт `ок` или `красный`.
5. Итог переносится в `e2e/reports/<дата>-<персона>.md` по шаблону `e2e/agent/REPORT.md`.

## Правила агента

- Работает только в аккаунте своей персоны. Чужие аккаунты, учётные записи и компании не трогает.
- Не выходит за `zone` персоны. Если нужный экран закрыт для её роли, это тоже проверка, и
  результат записывается как ожидаемый отказ.
- Для каждого шага сначала читает страницу (`get_page_text` или `read_page`), потом действует.
  Скриншот делается на каждом «красном» шаге.
- Ошибки консоли браузера (`read_console_messages`) и сетевые ошибки (`read_network_requests`)
  записываются, даже если экран выглядит нормально.
- Ничего не удаляет и не сбрасывает. Деньги и счета создаются только в сценарии, где это прописано.
- Не выкладывает ничего наружу и не отправляет письма.

## Что считать красным

- шаг дал другой результат, чем написано в ожидании;
- экран показывает данные чужой компании или то, что стоит в `must_not_see`;
- на экране есть ошибка, которой не должно быть (сообщение «ошибка», пустой экран, 500);
- ошибка в консоли на затронутом экране.

Шаг, который не удалось выполнить из-за самого интерфейса (нет кнопки, не открывается), тоже
красный, с описанием того, чего не хватило.
