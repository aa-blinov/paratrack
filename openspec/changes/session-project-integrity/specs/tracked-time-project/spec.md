# Spec Delta

## Purpose

Определяет, в каком проекте учитывается каждая сессия времени. Проект по умолчанию берётся от активности. Переопределение действует только на одну сессию, поэтому старт таймера с другим проектом или правка одной записи не меняют историю, отчёты и выставленное время соседних записей.

## ADDED Requirements

### Requirement: Сессия учитывается в проекте своей активности по умолчанию

Сессия времени без собственного проекта SHALL учитываться в проекте своей активности во всех отчётах, целях, счетах и расчётах выплат.

#### Scenario: Сессия без своего проекта
- **WHEN** сессия не имеет собственного проекта, а её активность привязана к проекту P
- **THEN** сессия учитывается в проекте P в отчёте по проекту, в целях и в счёте

### Requirement: Старт с другим проектом меняет только новую сессию

Старт таймера с проектом, который отличается от проекта активности, SHALL записывать этот проект только на новую сессию. Проект активности и сессии, созданные раньше, MUST оставаться без изменений.

#### Scenario: Старт с другим проектом
- **WHEN** пользователь запускает таймер на активности A, привязанной к проекту P1, и выбирает проект P2
- **THEN** новая сессия учитывается в проекте P2, активность A остаётся в проекте P1, а закрытые сессии активности A остаются в проекте P1

#### Scenario: Первый проект активности
- **WHEN** пользователь запускает таймер на активности без проекта и выбирает проект P, а ни одна сессия активности не включена в счёт
- **THEN** активность получает проект P, её прежние сессии без собственного проекта учитываются в P, а новая сессия наследует P

#### Scenario: Первый проект при выставленных сессиях
- **WHEN** пользователь запускает таймер на активности без проекта, у которой есть сессия в счёте, и выбирает проект P
- **THEN** активность остаётся без проекта, а новая сессия учитывается в проекте P как собственный проект

### Requirement: Правка проекта касается одной сессии

Правка проекта одной сессии SHALL менять проект только этой сессии. Остальные сессии и активность MUST сохранить свой проект. Правка SHALL показывать пользователю до сохранения, какая сессия меняется.

#### Scenario: Исправление проекта одной записи
- **WHEN** пользователь на странице проверки и правки меняет проект одной сессии с P1 на P2 и подтверждает
- **THEN** эта сессия учитывается в проекте P2, а все остальные сессии активности остаются в проекте P1

#### Scenario: Предупреждение до сохранения
- **WHEN** пользователь выбирает новый проект для сессии
- **THEN** до сохранения показано название сессии и то, что другие записи не меняются

### Requirement: Выставленная сессия проект не меняет

Сессия, включённая в счёт, MUST NOT менять свой проект ни при старте, ни при правке. Попытка SHALL быть отклонена с понятной причиной.

#### Scenario: Попытка сменить проект у выставленной сессии
- **WHEN** пользователь пытается поменять проект сессии, которая уже включена в счёт
- **THEN** изменение отклоняется, проект сессии остаётся прежним, а пользователь видит причину

### Requirement: Назначение проекта активности не переписывает переопределённые сессии

Назначение проекта активности менеджером SHALL применяться только к сессиям этой активности без собственного проекта и не выставленным в счёт. Сессии с собственным проектом MUST сохранить его.

#### Scenario: Смена проекта активности
- **WHEN** менеджер назначает активности A проект P3, а одна её сессия уже учитывается в проекте P2
- **THEN** сессии без собственного проекта переходят в P3, а сессия в P2 остаётся в P2

### Requirement: Отчёты считают сессию в её действующем проекте

Отчёты, цели и счета SHALL относить сессию к её действующему проекту: собственному, если он задан, иначе проекту активности.

#### Scenario: Отчёт по проекту после переопределения
- **WHEN** сессия активности A с проектом P1 переопределена на P2 и попадает в отчёт
- **THEN** её время входит в отчёт по P2 и не входит в отчёт по P1
