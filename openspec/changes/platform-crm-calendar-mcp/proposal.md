# Proposal

## Why

Владелец решил сделать paratrack agent-like: люди и агенты работают с одними сущностями платформы. Сейчас клиент в платформе только справочник для счетов. Нет ни воронки продаж, ни нескольких контактов, ни истории общения, ни общего календаря событий. Агент не может работать с платформой, кроме как через уже существующий `/api/v1` с ограниченным набором ресурсов и без записи в клиенты, задачи и календарь.

Решение D-1 («CRM вне продукта», `docs/backlog/README.md`) пересматривается этим change: по решению владельца CRM входит в платформу. Причина: без неё нельзя закрыть ведение клиентов и продаж в одном месте, где уже есть учёт времени и счета.

## What Changes

- Клиентская CRM: контакты клиента (несколько людей с ролью), сделки по стадиям воронки с суммой и датой следующего шага, лента активностей (звонок, встреча, заметка), напоминания о просроченном следующем шаге. Стадии фиксированные: новая, в работе, предложение, выиграна, проиграна. Настраиваемые стадии не входят в этот change.
- Общий календарь событий команды: событие с началом, концом, местом, заметкой, участниками из команды и необязательной привязкой к проекту или клиенту. Видно всем участникам пространства.
- MCP-сервер на `/mcp`: агент вызывает инструменты для клиентов, контактов, сделок, активностей, событий календаря, проектов, задач, сессий времени и сводного отчёта. Вход тот же, что у `/api/v1`: токен `pt_`, роли и флаг «только чтение» действуют как есть.
- Модули: `crm` и `calendar` добавляются в наборы «Фрилансер» и «Студия или команда». Режим «Для себя» их не включает.
- **BREAKING** для решения D-1: `docs/backlog/crm.md` пункты CRM-01..CRM-11 отменены в прошлых сессиях. Этот change заводит новые пункты CRM-12 и далее, старые не возвращает.

Не входит в этот change: настраиваемые стадии, автоматическое создание проекта при выигранной сделке, приём заявок с сайта через API, email и push-напоминания (только список просроченных в интерфейсе), синхронизация календаря с Google или Outlook, OAuth для MCP, стриминг ответов MCP через SSE.

## Capabilities

### New Capabilities
- `client-crm`: контакты, сделки и воронка, активности, напоминания о следующем шаге.
- `team-calendar`: общие события команды, участники, привязка к проекту и клиенту, видимость.
- `mcp-server`: протокол MCP поверх HTTP на `/mcp`, аутентификация токеном `pt_`, набор инструментов над сущностями платформы, ошибки и права.

### Modified Capabilities
<!-- Нет. Существующие правила клиентов, токенов и /api/v1 не меняются, новые инструменты их только используют. -->

## Impact

- `internal/db`: новые таблицы контактов, сделок, активностей, событий и участников событий в `schema_compat.go`, запросы и проверки прав внутри транзакций.
- Новые workflow-пакеты `internal/crm` и `internal/calendar`, пакет протокола `internal/mcpwire` без зависимостей, классифицируются в `scripts/architecture/40-package-roles.sh`.
- `internal/web`: HTTP-адаптер MCP и инструменты, JSON-эндпоинты CRM и календаря, страницы `/crm` и `/calendar` в React (`web/src/crm`, `web/src/calendar`), пересборка бандла.
- `internal/i18n/dict/ru.json` и `en.json`: новые ключи парами.
- `docs/PRODUCT.md`, `docs/backlog/crm.md`, `docs/backlog/README.md` (D-1 и новые пункты), `docs/MCP.md` с описанием инструментов.
- Существующие пространства получают модули по набору, без миграции данных. Клиенты остаются прежними, контакты создаются отдельно.
