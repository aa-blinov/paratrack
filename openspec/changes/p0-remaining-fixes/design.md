# Design

## Context

Три независимых места, одна тема: интерфейс должен говорить то, что есть.

- Отказ по утверждённой неделе: `model.SessionApprovalLockError{From, To}` создаётся в `internal/db/timesheet_approvals.go:41` и уже несёт границы недели. Его разбирают `writeSessionLockConflict` (`handlers_timers.go:240`, отдаёт `ts.weekApproved`) и `respondTimesheetWriteError` (`handlers_timesheet.go:267`, тот же ключ в ячейке табеля). `handleBackfill` (`handlers_backfill.go:68-96`) эту ошибку не разбирает и уходит в `err.internal` с записью в лог. Правка сессии (`handleUpdateSession`) идёт через `writeSessionUpdateError` и получает короткий текст без недели.
- Отчёт «Загрузка команды»: `handleReportRun` (`handlers_reports_marketplace.go:203-205`) задаёт окно по умолчанию `from = now - 30 дней`, `to = now + 24ч`. План берётся тем же окном (`PlannedMinutesByUser`, `[from, to)`), поэтому дни после сегодня не попадают. Колонка «Доля» идёт из `reportRow.Share`, то есть из доли строки в `TotalSeconds`.
- Удаление участника: `team-members-page.tsx:26` показывает форму «Убрать» всем, кроме себя. В той же строке есть `ownerLocked = owner && !IsOwner` (строка 21), которую кнопка не учитывает. Сервер отказывает администратору при удалении владельца (`internal/teams/members.go:113`).

## Decisions

### D1. TIME-03: один текст отказа на все пути записи

Одна функция `weekLockedMessage(lang, lock *model.SessionApprovalLockError) string` строит текст из границ недели и ключа `ts.weekLocked` с двумя `%s`. Даты выводятся в часовом поясе пользователя (`userLoc(r)`) через `fmtDate`, которым уже печатается `PeriodLabel` отчётов. Конец недели в ошибке исключающий, поэтому показываем `To - 1 день`.

Вызывают её четыре места: `writeSessionLockConflict`, `respondTimesheetWriteError`, новая ветка в `handleBackfill` и тот же `writeSessionLockConflict` для `/api/v1`. Ключ `ts.weekApproved` (ru и en) заменяется на `ts.weekLocked`, чтобы не осталось двух текстов на одно событие. Проверка паритета словарей (`go test ./internal/i18n`) это подтвердит.

Ветка в `handleBackfill` стоит до `ErrAlreadyBilled` и не пишет лог: это ожидаемый отказ, а не внутренняя ошибка.

Правило блокировки (`lockApprovedWeek`, `lockApprovedSpan`) не трогаем.

Про правку сессии. По коду она уже отдаёт `ts.weekApproved`, а не общую ошибку, как написано в бэклоге. Общая ошибка может появляться в другом пути правки. Поэтому до кода проверяем PATCH на QA-стенде: пишем сессию в утверждённую неделю, смотрим ответ. Если общая ошибка воспроизводится, причину ищем по логу, и это меняет задачу, а не текст.

### D2. PLAN-01: план и факт за один период, по умолчанию текущая неделя

Окно по умолчанию для отчёта с группировкой по людям (`tpl.GroupBy == ReportGroupUser`, то есть `showPlan`) становится текущей неделей: `from = startOfWeek(r, now)`, `to = from + 7 дней`. Правило первого дня недели берётся из `startOfWeek` (`date_helpers.go:49`), которое уже использует интерфейс.

Почему неделя, а не «30 дней до конца недели»: отношение факта к плану должно считаться по одним и тем же дням. Если прошедшие 30 дней и будущая неделя попадают в одно отношение, загрузка получается занижена на будущую часть плана. Для недели это понятно: «сделано из плана на неделю».

Другие отчёты окно по умолчанию не меняют: изменение касается только планового отчёта.

`PlannedMinutesByUser` и SQL не меняем: он уже суммирует `[from, to)`, и исправляется окно, а не запрос.

Колонка «Загрузка» считается в React-странице из уже приходящих полей `Secs` и `PlannedSecs`: `Secs / PlannedSecs * 100`, пусто, если плана нет. Формат процента берём у `formatShare(value, lang)` из `web/src/lib/utils.ts`. Колонка «Доля» в этом отчёте заменяется, в остальных остаётся. Серверный ответ и `reportRow` не меняем.

CSV отчёта не меняется (см. proposal, раздел «Совместимость»).

### D3. ADM-03: кнопка только там, где сервер её примет

Условие формы «Убрать» становится `!ownerLocked && member.UserID !== data.User.ID`. `ownerLocked` уже вычислен в той же строке, поэтому это одна правка. Сервер не меняем: проверка в `internal/teams/members.go` остаётся основной защитой.

Бандл `internal/web/static/ui` пересобирается и коммитится. Сборка не идёт параллельно с Go-тестами (гонка embed).

## Risks

- Текст отказа длиннее прежнего: в узкой колонке ячейки табеля фраза переносится. Смягчение: проверка на 375 px в e2e.
- Окно по умолчанию меняется только для планового отчёта. Пользователь, который привык к 30 дням, увидит неделю. Смягчение: явный период по-прежнему работает, записываем в changelog.
- Правка сессии: если общая ошибка воспроизведётся на стенде, причина лежит вне `writeSessionLockConflict`. Смягчение: сначала воспроизведение, потом код; без воспроизведения TIME-03 закрываем только по ручному вводу и тексту и отмечаем это в бэклоге.

## Verification

- Go: `weekLockedMessage` в ru и en с датами недели (граница конца недели не утекает); ручной ввод в утверждённую неделю отвечает текстом с датами и не пишет в лог как внутреннюю ошибку; правка сессии в утверждённую неделю отвечает тем же текстом; `/api/v1` отдаёт 409 с этим текстом; плановый отчёт по умолчанию охватывает текущую неделю, и план 30 часов на неделю попадает в сумму целиком (включая будущие дни); для Sunday-настройки неделя начинается с воскресенья.
- Web: `npm run test:unit` для функции загрузки (нет плана, план 0, план больше факта, факт больше плана); `npx tsc --noEmit -p .`.
- e2e (QA-стенд, холодный старт `scripts/qa-env.sh down && up`): ручной ввод в утверждённую неделю показывает даты и подсказку; колонка «Загрузка» в «Загрузка команды» и отсутствие «Доли» там же; администратор не видит «Убрать» у строки владельца, а у участника видит.
- `make verify` с `GOTOOLCHAIN=go1.27.3` (локальное ограничение govulncheck, см. прошлое изменение); `scripts/check-architecture.sh` с `rg` в `/usr/bin`.

## Open questions

- Текст подсказки. Бэклог пишет «Попросите владельца снять утверждение», но сервер разрешает снять утверждение и администратору (`CanManage`). Принято: «Попросите владельца или администратора снять утверждение». Если нужно только слово «владелец», меняется один ключ.
- Окно по умолчанию. Принято: текущая неделя только для планового отчёта. Если нужны прошлые 30 дней, нужно решить, как считать загрузку за прошедшие дни, и это отдельный разговор.
- Правка сессии с общей ошибкой. Не воспроизведена по коду; проверяем на стенде в первой задаче.
