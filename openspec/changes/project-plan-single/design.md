# Design

## Context

Страница проекта (`web/src/projects/project-detail.tsx`) получает данные из `projectPlan` (`internal/web/project_plan.go`). Данные три плана:
- `PlannedLabel`: сумма `planned[member]` по участникам, `planned` из `ProjectPlanByMember` → `PlannedMinutesForProject` за все дни.
- строки таблицы «По людям»: тот же `planned[member]`, плюс `tracked[member]` для руководителя и руководителя проекта.
- `RemainingLabel`: оценка минус учтённое минус `PlannedAhead` (план с сегодняшнего дня), подсказка `proj.remainingHint`.

Карточка «Спланировано за всё время» (`proj.plannedAll`) выводит `PlannedLabel` и дублирует сумму строк таблицы. В тестах и e2e её нет.

## Decisions

### D1. Карточку убираем, итог переносим в таблицу

Карточка `SummaryCard` с `proj.plannedAll` удаляется. Итог выводится строкой в конце таблицы «По людям»: подпись «Итого за всё время» (`proj.totalAllTime`), колонка плана: `PlannedLabel`, колонка учтённого: итог `TrackedLabel`, только если `CanManage`. Таблица уже показывает колонку учтённого для руководителя, так что строка итога совпадает с её колонками.

Почему не наоборот (убрать колонку плана из таблицы): колонка по людям нужна, чтобы понимать, кто загружен. Дубль: это сумма, а не строки.

### D2. Итог считается из тех же строк

`PlannedLabel` уже равен сумме `planned` по участникам, которые попадают в таблицу. Чтобы итог и строки не разошлись, `TrackedLabel` считается в том же цикле по `members`, что и `trackedTotal` в `projectPlan` (сейчас он вычисляется и не выводится). Расхождения быть не может: оба берутся из одного прохода.

### D3. Окно остатка не меняем

`RemainingLabel` по-прежнему считается от плана с сегодняшнего дня. Подсказка `proj.remainingHint` уже говорит «запланированное на будущие дни», поэтому два окна названы явно. Если руководитель захочет, чтобы остаток и итог считались одним окном, это отдельное решение (вопрос ниже).

### D4. Строка итога только при людях в таблице

Если таблица пуста (`People` пуст), выводится прежнее сообщение `proj.noPlanned`, итоговой строки нет: итог нуля при пустой таблице не имеет смысла.

## Risks

- Пропажа карточки может показаться потерей информации. Смягчение: итог переехал в таблицу с той же суммой и явным периодом.
- Строка итога в узком экране (мобильный) должна переноситься. Проверка на 375 px в e2e: колонки таблицы уже адаптивны (`TableHead`), строка итога использует те же классы.
- `TrackedLabel` для участника без права на учёт не выводится (колонка скрыта), так что поле в данных не утекает: его считают только при `showTracked`, а вывод ограничен `CanManage`.

## Verification

- Go, `internal/web`: `projectPlan` на проекте с двумя людьми: `PlannedLabel` равен сумме строк, `TrackedLabel` равен сумме учтённого для руководителя и пуст для участника без права; пустой план даёт пустой `People` и пустой итог.
- Web: `npx tsc --noEmit -p .`; карточка «Спланировано» не выводится; строка итога выводится при людях в таблице.
- `go test ./internal/i18n` (паритет `proj.totalAllTime`).
- e2e на холодном стенде `e2e/test_project_plan_single.py`: на проекте два человека с планом; страница показывает одну сумму плана, строку «Итого за всё время» равную сумме строк; карточки «Спланировано за всё время» нет; на 375 px строка итога не выходит за экран.
- `make ui` (бандл), `make verify` с `GOTOOLCHAIN=go1.27.3` (или без, т.к. go.mod уже 1.27.3), `scripts/check-architecture.sh`.

## Open questions

- Окно остатка по смете: оставить «от сегодня» (по умолчанию, как сейчас) или перевести на весь период, чтобы остаток и итог считались одним окном. Меняется одна строка в `projectPlan`, но меняется и смысл цифры «Осталось», поэтому решение за руководителем.
