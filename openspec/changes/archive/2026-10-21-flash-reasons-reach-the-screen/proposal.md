# Proposal

## Why

Форма создания счёта, если неоплаченных часов в периоде нет, молча возвращает на список: ни счёта, ни причины на экране (FIN-24, P1). Пункт бэклога описывает симптом, а причина общая.

Проверено на QA-стенде: после отправки формы в URL есть флеш «За этот период нечего выставлять. …», а данные страницы счетов содержат пустой `Flash`. Причина в `encodeFlash` (`internal/web/flash.go`): функция возвращает текст без экранирования, и редирект склеивает его прямо в URL. Текст сообщения содержит «;», а Go со времён 1.17 не принимает «;» в query-строке и молча отбрасывает весь параметр `flash`. Проверено отдельным запуском Go: `url.Parse` с «;» даёт пустой `flash`, с `url.QueryEscape` значение возвращается целиком.

Так теряются все флеш-сообщения, в которых есть «;», «&», «#», «+» или «%»: и текст из словаря, и имена клиентов и проектов, подставленные в сообщение. Таких мест много: `encodeFlash` вызывают 119 раз, из них 102 раза результат склеивается в URL без экранирования (14 экранируют сами, 2 передают в `url.Values`, и ещё 1 : определение).

## What Changes

- `encodeFlash` возвращает значение, готовое для query-строки (`url.QueryEscape`). Каждый редирект с `?flash=` + `encodeFlash(...)` начинает передавать сообщение целиком, с любыми символами.
- Сырой код флеша (`e:` + текст, без экранирования) остаётся отдельной функцией `flashCode` для мест, где значение кладётся в `url.Values`: там кодирование делает сам `url.Values.Encode`.
- Места, которые уже экранировали сообщение сами (`url.QueryEscape(encodeFlash(...))` в 14 местах, включая `importFlash` в `handlers_integrations.go`), убирают лишнее экранирование: иначе сообщение кодируется дважды и на экране не читается.
- Форма создания счёта при отсутствии неоплаченных часов показывает причину как ошибку на странице счетов (FIN-24).
- Декодирование флеша (`decodeFlash`) не меняется: оно получает значение после `r.URL.Query()` и разбирает префикс `e:` как раньше.

## Capabilities

### New Capabilities
- `form-flash-messages`: ответ формы доходит до страницы целиком, каким бы символом ни был набран текст, и отказ показывается как ошибка.

### Modified Capabilities
Нет. В `openspec/specs/` спецификаций флешей нет.

## Impact

- Go: `internal/web/flash.go` (`encodeFlash`, новая `flashCode`), 102 места с сырой склейкой (после изменения `encodeFlash` корректны без правки вызова), 14 мест с лишним `url.QueryEscape` (включая `importFlash` в `handlers_integrations.go`), 2 места с `url.Values` в `handlers_invites.go` (переходят на `flashCode`).
- Тесты: round-trip тест (`encodeFlash` → редирект → `r.URL.Query()` → `decodeFlash`) с «;», «&», «#», «+», «%» и кириллицей; тест-страж, который падает, если кто-то снова пишет `url.QueryEscape(encodeFlash(...))`; web-тест на данные страницы счетов для причины отказа.
- e2e: `e2e/test_invoice_no_billable_reason.py` на холодном стенде: период без часов → причина видна на странице счетов.
- Совместимость: URL с флешами меняются (значение экранировано иначе), старые закладки с сырыми флешами не нужны. Сообщения, которые раньше терялись молча, теперь появляются: это и есть цель.
- Вне scope: единый хелпер для всех флешей по всему приложению, отказ оплаты и создание ссылки на оплату (UI-02), FIN-14, другие FIN- пункты.
