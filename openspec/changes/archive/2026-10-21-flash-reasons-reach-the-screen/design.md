# Design

## Context

Ответ формы возвращается редиректом `…?flash=<значение>`. Значение строит `encodeFlash(ok, msg)` (`internal/web/flash.go`): для ошибки это `"e:" + msg`, для успеха `msg`. Страница читает его через `r.URL.Query().Get("flash")` и разбирает `decodeFlash` (`handlers_teams.go`), где префикс `e:` делает сообщение ошибкой.

Текущее состояние, проверенное по коду:
- `encodeFlash` вызывают 119 раз. 102 вызова склеивают результат в URL без экранирования; 14 экранируют сами (`url.QueryEscape(encodeFlash(...))`, из них два в `importFlash` в `handlers_integrations.go`); 2 кладут его в `url.Values` в `handlers_invites.go` (там `Encode` экранирует сам); и есть определение.
- Сырая склейка ломается на «;» (`url.Query` отбрасывает весь параметр), а на «&», «#», «+», «%» : портит значение.
- Двойное экранирование даёт текст в процентах, который `decodeFlash` не узнаёт, и сообщение выглядит как мусор.

## Decisions

### D1. Экранирование в одной функции

`encodeFlash` возвращает `url.QueryEscape` от сырого значения. Тогда все 102 сырые склейки становятся правильными без правки вызова: это главное, зачем меняется функция. Сырое значение остаётся в новой функции `flashCode(ok, msg)` (текущее поведение `encodeFlash`), она нужна только там, где значение кладётся в `url.Values`.

Альтернатива : экранировать в 102 местах : отклонена: это 102 правки вместо одной, и любой пропуск снова даст тихую потерю.

### D2. Убрать двойное экранирование

Во всех 14 местах с `url.QueryEscape(encodeFlash(...))` обёртка становится лишней и удаляется. `importFlash` возвращает `encodeFlash(...)`, и `fmt.Sprintf("...?flash=%s", …)` его не меняет. Два места в `handlers_invites.go` переходят на `flashCode`: `url.Values.Encode` экранирует значение один раз.

Итого правок: 14 удалений обёртки и 2 замены на `flashCode`. Остальные 102 вызова не меняются.

### D3. Страж от возврата двойного экранирования

Тест в `internal/web` (`flash_escape_test.go`) разбирает исходники пакета через `go/parser` и падает, если найден вызов `url.QueryEscape` с аргументом `encodeFlash(...)`, либо `url.Values`, в который передан `encodeFlash(...)`. Сообщение теста называет файл и строку. Это проще и надёжнее, чем проверка на уровне текста, и не требует нового инструмента в `scripts/architecture`.

### D4. Round-trip тест

`flash_roundtrip_test.go`: для набора сообщений с «;», «&», «#», «+», «%», кириллицей и пробелами `encodeFlash` → `http.Redirect` → `url.Parse(Location)` → `r.URL.Query().Get("flash")` → `decodeFlash` возвращает исходный текст и правильную полярность (ошибка или успех). Набор включает реальные сообщения словаря, в том числе «За этот период нечего выставлять. … в других счетах; идущий таймер сначала остановите.»

### D5. Причина отказа на странице счетов

Обработчик `handleInvoiceCreate` уже формирует правильный ключ сообщения, поэтому меняется только доставка. Web-тест: POST `/invoices` за период без часов → `Location` → страница счетов → `data.Flash` содержит причину, `FlashOK` false. E2E `e2e/test_invoice_no_billable_reason.py` проверяет то же на холодном стенде, глазами пользователя.

## Risks

- Существующие тесты, которые проверяют сырые строки в `Location` (`handlers_projects_test.go`, `prefs_test.go`), могут ожидать старый вид. Смягчение: прогон web-пакета; правка только там, где проверка была на сырой текст флеша, а не на поведение.
- Сообщения, которые раньше терялись, теперь появляются. Это цель, но может затронуть e2e, которые опирались на отсутствие текста. Смягчение: прогон связанных e2e (`test_accounting_integrity`, `test_week_lock_and_load`, `test_admin_audit_trail`, `test_member_roles_on_screen`).
- Старые закладки с сырыми флешами перестанут работать корректно только для сообщений с «;» и подобными. Для остальных значение идентично после декодирования.

## Verification

- `go test ./internal/web/…` для round-trip и стража, полный Go-прогон (`scripts/go-packages.sh | xargs scripts/test.sh`) с кодом 0.
- e2e на холодном стенде: `test_invoice_no_billable_reason.py`, плюс перечисленные связанные сценарии.
- `make verify` с `GOTOOLCHAIN=go1.27.3`, `scripts/check-architecture.sh`.
- Бандл не меняется: правка только в Go. `make ui` не нужен, если в `web/src` ничего не менялось; проверяем `git status` перед коммитом.

## Open questions
