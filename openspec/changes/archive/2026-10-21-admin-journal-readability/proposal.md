# Proposal

## Why

Журнал на `/settings/audit` записывает нужные события (их добавил `admin-audit-trail`), но читать его трудно. Строка показывает время, действие, цель и IP. Исполнителя в строке нет вовсе: он виден только в фильтре «Кто». Смена роли выглядит как «Изменена роль: 12», потому что цель: это id участника. Meta не выводится, поэтому имя отозванного токена на экране не видно. Фильтр «Кто» строится из текущего состава, и удалённый участник из него выпадает, а выбор такого человека молча не сужает список (ADM-02, P1).

Проверено в коде: `web/src/settings/audit-page.tsx` выводит четыре поля строки (`time`, `action`, `target`, `ip`), `auditRow` в `internal/web/handlers_audit.go` не содержит исполнителя; `requestedAuditFilters` принимает `user` только из `people`, а `people` строится из `members`; `teamops` пишет `member.role` с id участника в цели и ролью в meta.

## What Changes

- Каждая строка журнала показывает исполнителя по имени. Имя берётся из таблицы пользователей по id, поэтому бывший участник остаётся именованным. Пустое имя заменяется адресом, как в списке участников.
- Цель и деталь строки читаются по-человечески. Сервер собирает их по действию: для `member.role` «Иван Петров: администратор»; для `auth.api_token_create` и `auth.api_token_delete` имя токена; для `member.remove` и `invoice.delete` цель уже человеческая (имя, номер счёта), деталь скрыта, потому что meta: служебный `user:<id>` или `invoice:<id>`.
- Цель восстановления (`workspace.restore`) показывает название пространства вместо `team:<id>`.
- Фильтр «Кто» включает всех, кто оставил строки в журнале: текущих участников и бывших. Список берётся из `DISTINCT user_id` журнала, а не из текущего состава. Выбор бывшего участника сужает список.
- Ранее записанные строки не меняются: отображение считается на сервере при чтении.

## Capabilities

### New Capabilities
Нет.

### Modified Capabilities
- `team-audit-trail`: строка журнала показывает исполнителя по имени, цель и деталь по-человечески, фильтр «Кто» включает бывших участников.

## Impact

- Go: `internal/web/handlers_audit.go` (строка `auditRow` с исполнителем и деталью, фильтр `people` из журнала), `internal/db/audit.go` (`DISTINCT user_id` по команде), чтение имён пользователей по id (новый метод в `internal/db`, без обхода `teams.FindByIDs`), название пространства для цели `workspace.restore` берётся при чтении через существующий `teams.FindByIDs`; записи не меняются.
- Web: `web/src/settings/audit-page.tsx` (колонка исполнителя, деталь в строке), типы в `web/src/dashboard/types.ts`.
- i18n: подписи для деталей смены роли (роли `owner`, `admin`, `member` уже есть в словаре) и заголовок колонки исполнителя в ru и en.
- Бандл `internal/web/static/ui` пересобирается и коммитится.
- Тесты: Go на строку с исполнителем и деталью для каждого действия из `admin-audit-trail`; на фильтр по бывшему участнику; на отсутствие служебного `user:<id>` в строке. e2e: смена роли показывает имя и роль; бывший участник в фильтре.
- Совместимость: ответ `/settings/audit` получает новые поля. Старые строки журнала не меняются. CSV журнала не появляется, экспорт вне scope.
- Вне scope: выгрузка журнала в файл, экспорт журнала в CSV, цели `session:<id>` у правок сессии (они остаются кодом, отдельный пункт), другие ADM-, FIN-, TIME- пункты.
