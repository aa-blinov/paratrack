# Design

## Context

`tasks.assignee_user_id` хранит исполнителя. Удаление участника (`internal/memberadmin`, `/api/team/members/{id}/remove`) этот столбец не трогает: в коде нет записи в `tasks` при удалении. `handleTasks` и `handleTasksAPIList` строят `taskItem` через `taskItems`, а имена берут из `taskPeople`, то есть из списка участников команды. Если исполнителя в этом списке нет, `AssigneeName` пустое, и интерфейс пишет «Не назначен» (`tasks-page.tsx`, строка с `tasks.nobody`).

См. proposal.md, раздел «Why». Пункт ADM-05 в `docs/backlog/admin.md` говорит, что при удалении участника «задачи уходят без исполнителя». По коду это неверно: ссылка остаётся. Я это учитываю здесь и предлагаю поправить текст ADM-05 при закрытии.

## Goals / Non-Goals

**Goals:**
- Различить «не назначен» и «исполнитель вне команды» в таблице и мобильной карточке.
- Не менять данные: ссылка на исполнителя сохраняется.

**Non-Goals:**
- Очистка исполнителя при удалении участника. Это решение о данных, а не отображение, и не входит в TASK-06.
- API v1: поле `assignee_name` остаётся пустым, как и было; отдельного флага в API не добавляем.
- Страница задачи (`task-detail.tsx`): там переназначение, предупреждение там не нужно для этого пункта.

## Decisions

**D1. Признак считается на сервере.** В `handleTasks` и `handleTasksAPIList` через `taskItems`: `AssigneeGone = task.AssigneeID > 0 && names[task.AssigneeID] == ""`. Альтернатива: отдавать список участников в React и считать там. Отвергнута: логика уже на сервере, и тесты читают данные страницы, а не разбирают интерфейс.

**D2. Текст и стиль.** Новый ключ `tasks.assigneeGone`: ru «Исполнитель вне команды», en «Assignee left the team». Выделение через `text-destructive`, как у других предупреждений в таблицах.

**D3. Мобильная карточка.** Строка исполнителя в карточке (`tasks-page.tsx`, строка с `task.AssigneeName &&`) тоже показывает предупреждение, иначе на телефоне опять «ничья».

## Risks / Trade-offs

- Задача, назначенная на участника, который удалён давно, будет показывать предупреждение бессрочно, пока её не переназначат. Это ожидаемо: решение о задаче принимает человек.
- Если участник вернётся, предупреждение исчезнет без действий. Это соответствует спеке.
- ADM-05 остаётся с неверным текстом до отдельной правки. Её делаем вместе с закрытием TASK-06.
