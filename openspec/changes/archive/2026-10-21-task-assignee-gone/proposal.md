# Proposal

## Why

Когда участник уходит из команды, его задачи не теряют исполнителя в базе: `tasks.assignee_user_id` остаётся на нём. Таблица задач берёт имя из списка участников команды, не находит его и пишет «Не назначен». Человек видит задачу как ничью, хотя у неё есть исполнитель, которого больше нет в команде, и никто не получает напоминания её взять.

Пункт TASK-06 в `docs/backlog/tasks.md` (P1, S). Источник: администратор, кейс 3.

## What Changes

- Задача, у которой исполнитель не входит в команду, в таблице и в мобильной карточке показывает предупреждение «Исполнитель вне команды», а не «Не назначен».
- Задача без исполнителя показывает «Не назначен», как раньше.
- Исполнитель задачи в базе не меняется: при уходе участника задача сохраняет ссылку, так что при возвращении участника или восстановлении пространства имя вернётся.

## Capabilities

### New Capabilities
- `task-assignee-state`: как таблица задач показывает исполнителя, который больше не в команде, отдельно от задачи без исполнителя.

### Modified Capabilities
Нет.

## Impact

- `internal/web/handlers_tasks.go`: поле `AssigneeGone` в `taskItem`, вычисляется по списку участников.
- `web/src/dashboard/types.ts`: поле `AssigneeGone` в типе задачи.
- `web/src/tasks/tasks-page.tsx`: таблица и мобильная карточка.
- `internal/i18n/dict/ru.json` и `en.json`: ключ `tasks.assigneeGone`.
- `internal/web/static/ui/`: пересборка бандла.
- Вне scope: API v1 (поля ответа не меняются), страница задачи, ADM-05 (там текст пункта расходится с кодом, см. design.md).
