# Design

## Context

`timeparse.ParseDuration` (`internal/timeparse/timeparse.go`) читает длительность из правки сессии (`handlers_session_edits.go`), из CLI (`timers_add.go`, `goals.go`) и из API. Двоеточия парсер не знает, поэтому `1:30` отвергается с текстом «например 1ч 30м».

Поле редактора получает значение от `durationToHuman` (`formatters.go`) через `session_view.go`. Сейчас это «1 ч 30 мин». Клиентские парсеры табеля (`cellMinutes`) и расписания (`parseMinutes`) уже понимают `H:MM`, а подсказка табеля пишет «Введите 1:30 или 90 минут». См. proposal.md, раздел «Why».

## Goals / Non-Goals

**Goals:**
- Одна форма длительности: та, что видит человек в поле, в подсказке и в ошибке, та же, что принимает сервер.
- Прежние формы продолжают работать в CLI, API и в старых сохранённых сценариях.
- Подсказка редактора видна на любом экране.

**Non-Goals:**
- Удаление старых форм из парсера. Это ломает CLI и API без пользы.
- Формат в отчётах, CSV и на обзоре.
- Обрезка секунд при правке заметки (см. «Риски»).

## Decisions

**D1. `H:MM` в `ParseDuration`, а не отдельный парсер для редактора.** Добавляем ветку до токенизатора: `^\d{1,3}:[0-5]\d$`, часы любые, минуты до 59. Ноль отвергается тем же правилом «должно быть положительным». Альтернатива: парсер только для редактора. Отвергнута: CLI и API тогда принимали бы другое, чем поле.

**D2. Поле показывает `H:MM` для сессий от минуты.** `durationToHuman` для `sec >= 60` возвращает `H:MM`. Для `0 < sec < 60` остаётся «45 с», потому что `0:00` теряет секунды, которые человек видит. Альтернатива: оставить «1 ч 30 мин» в поле и принимать `H:MM` тоже. Отвергнута: тогда формат два, а пункт требует один.

**D3. Пример под полем, а не только placeholder.** Placeholder исчезает, как только в поле введено значение. Поэтому пример выводится отдельной строкой под полем: новый ключ `stats.durationFormat`. `ph.duration` меняется на `1:30` и остаётся подсказкой в пустом поле.

**D4. Подсказка редактора всегда видна.** Выражение `editorOpen ? editHint : editorFolded` заменяется на `editHint`. Ключ `stats.editorFolded` («Сами записи дня...») удаляем из обоих словарей: он нужен только здесь. Альтернатива: показывать обе строки с классами `lg:hidden`. Отвергнута: лишняя разметка ради текста, который дублирует подсказку.

**D5. Ошибка называет формат.** `err.sessionBadDuration`: «Укажите длительность как часы и минуты, например 1:30.» и английский аналог.

## Risks / Trade-offs

- **Секунды обрезаются при правке заметки. Это было и до change.** Редактор на каждом сохранении шлёт длительность (`save()` отправляет `duration` всегда), а сервер ставит длительность выше конца. Поэтому правка одной заметки у сессии 10:00:00–11:30:20 сдвигает конец на 11:30:00. Формат `H:MM` этого не меняет: `1 ч 30 мин` тоже отбрасывает секунды. Чинится отдельно: `save()` должен отправлять только изменённое поле или не отправлять длительность, если её не меняли. Здесь не трогаем, предлагаем отдельный пункт бэклога.
- Старые формы остаются, поэтому «один формат» означает один формат в интерфейсе и в подсказке, а не в парсере. Так проще не ломать CLI и API.
- Клиентские парсеры табеля и расписания принимают `H:MM` с ограничением минут `[0-5]\d`. Серверный парсер берёт то же правило, поэтому расхождения нет.
